# 8.2: Distributed Caching: Valkey, Redis, and Memcached


## The Critical Dialogue


**Student:** Should we use Redis/Valkey or Memcached? They both store data in RAM. Is one actually "Faster"?


**Principal:** You're choosing a **Threading Model**. Redis/Valkey is a **Soloist** (Single-threaded); Memcached is an **Orchestra** (Multi-threaded). To reach Principal level, we must analyze the **Slab Allocation** physics and the **I/O Multiplexing** mechanics. We move from "Stashing Data" to **Managing Memory Fragments**.

## 1. The Requirement: Global Distributed State


**The Problem:** In a fleet of 5,000 pods, each pod has its own L1. If Pod A updates a balance, Pod B still has the old one. We need a shared L2 "Source of Speed."

## 2. Source Archaeology: Memcached Slab Allocation


A Principal knows that memory fragmentation is the silent killer of cache performance.


> [!abstract] The Physics: Slabs vs. Malloc
. **The Problem:** Standard `malloc()` creates fragments. The cache becomes "Swiss Cheese."
. **The Solution:** Memcached uses **Slab Allocation**. It pre-divides memory into fixed-size chunks (e.g. 1KB, 2KB). 
. **The Result:** Zero fragmentation. When you store an object, Memcached puts it in the smallest slab that fits.
