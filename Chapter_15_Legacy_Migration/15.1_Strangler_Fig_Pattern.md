## The Critical Dialogue

**Student:** Our legacy Ledger is a 10-year-old Monolith. It's written in Java 8, it's slow, and everyone is afraid to touch it. I want to rewrite it from scratch in Spring Boot 3, but the business says "No, it's too risky." Am I stuck in the past forever?

**Principal:** A "Big Bang Rewrite" is the most common cause of architectural death. You spend 6 months building a new system that has no users, while the old system continues to grow bugs. To reach Principal level, we must master **Evolutionary Architecture**. We don't destroy the past; we consume it. We use the **Strangler Fig Pattern** to grow a new, high-performance system around the old one, one feature at a time. We move from "The Great Rewrite" to **Continuous Incremental Value**.

## 1. The Physics of the Strangler Fig

### 1.1 How to Kill a Monolith Safely

The Strangler Fig pattern (named after the vine that grows around a tree and eventually replaces it) is the industry standard for legacy mitigation.

> [!abstract] The 3 Phases of Evolution
> - **1. Interception:** Use an **Anycast Gateway** (Chapter 4.1) or an eBPF Proxy (Chapter 6.2) to route specific requests to the new service.
> - **2. Propagation:** Move one Bounded Context (Chapter 14.1) at a time. (e.g. move "Audit" first, then "Trading").
> - **3. Elimination:** When the old system is just an empty shell, you turn off the power. The tree is dead; the vine is the new tree.

---

## 2. Solution: The Anycast Interceptor

**The Principal Architecture:** We use the routing layer to hide the migration from the user.

- **Mechanism:** The user hits `api.ledger.com/v1/orders`.
- **The Gatekeeper:** The Gateway (Envoy or Nginx) checks its routing table.
- **The Handoff:** If the feature has been "Strangled," Envoy sends the request to the new **Spring Boot 3 / Loom** cluster. Otherwise, it goes to the **Java 8 Monolith**.

## 3. Source Archaeology: Spring HandlerMapping and Feature Flags

**`org.springframework.web.servlet.HandlerMapping`** (Spring MVC):
- The Strangler Fig interceptor is most elegantly implemented as a custom `HandlerMapping` with higher precedence than the default
- `AbstractHandlerMapping.setOrder(int)` — set a lower order number to take priority over `RequestMappingHandlerMapping`
- In the custom `HandlerMapping.getHandler(HttpServletRequest)`: check the feature flag, return the legacy handler bean if not yet strangled, or forward to the new service handler

**`org.springframework.web.reactive.function.client.WebClient`** (Spring WebFlux):
- Used by the Strangler Router to proxy matched requests to the new service: `WebClient.create("http://new-audit-service.internal").method(request.getMethod()).uri(request.getURI()).retrieve().bodyToMono(String.class)`
- Non-blocking proxy — the router does not consume a thread while waiting for the new service response

**`io.github.openfeaturehub.sdk.OpenFeatureAPI`** (OpenFeature standard, `dev.openfeature:sdk`):
- `OpenFeatureAPI.getInstance().getClient().getBooleanValue("audit-context-strangled", false)` — standardised feature flag evaluation
- Works with LaunchDarkly, Flagsmith, Unleash backends; same code regardless of provider
- Percentage rollout: evaluate the flag with a `userId` evaluation context to implement canary user targeting

**`org.springframework.web.filter.OncePerRequestFilter`**:
- Alternative to custom `HandlerMapping`: implement the Strangler Fig as a filter that forwards matched requests via `WebClient` and short-circuits the filter chain

**Envoy proxy configuration (YAML, for the gateway layer):**
```yaml
# routes evaluated in order — first match wins
- match:
    prefix: "/v2/audit"          # 1. Strangled path → new service
  route:
    cluster: new_audit_service
- match:
    prefix: "/"                  # 2. Everything else → monolith
  route:
    cluster: legacy_monolith
```

## 4. Principal Implementation: The Feature-Flag Switch

```java
// Principal Level: Strangler Router
@Component
public class MigrationRouter {
    private final FeatureFlagService flags;

    public String getTargetUrl(HttpServletRequest req) {
        String path = req.getRequestURI();

        // 1. Principal Rule: Check the 'Migration Flag'
        // If 10% of users are enabled for the 'New Audit' context...
        if (path.startsWith("/audit") && flags.isStrangled("audit-context")) {
            return "http://new-audit-service.internal";
        }

        // 2. Fallback to the monolith for everything else
        return "http://legacy-monolith.internal";
    }
}
```

### GOOD: Strangler Router with canary rollout and automatic fallback

```java
import org.springframework.stereotype.Component;
import org.springframework.web.servlet.HandlerMapping;
import org.springframework.web.reactive.function.client.WebClient;
import javax.servlet.http.HttpServletRequest;
import java.util.Map;
import java.util.concurrent.ConcurrentHashMap;
import java.util.concurrent.atomic.AtomicInteger;

/**
 * Strangler Fig Router.
 *
 * Migration state (stored externally in LaunchDarkly / OpenFeature):
 * - "audit-strangled"    = false  → 100% legacy
 * - "audit-strangled"    = true   → route by canary percentage
 * - "audit-canary-pct"  = 10     → 10% of users go to new service
 *
 * Fallback: if the new service returns 5xx, automatically fall back to
 * the legacy monolith and increment an error counter (circuit breaker).
 */
@Component
public class StranglerFigRouter {

    private final OpenFeatureClient featureFlags;
    private final WebClient newServiceClient;
    private final WebClient monolithClient;

    // Error rate tracking per route — used for automatic fallback
    private final Map<String, AtomicInteger> errorCounts = new ConcurrentHashMap<>();

    public StranglerFigRouter(OpenFeatureClient featureFlags) {
        this.featureFlags = featureFlags;
        this.newServiceClient = WebClient.create("http://new-audit-service.internal");
        this.monolithClient  = WebClient.create("http://legacy-monolith.internal");
    }

    public byte[] route(HttpServletRequest req) {
        String path = req.getRequestURI();
        String userId = req.getHeader("X-User-Id");

        // 1. Feature flag check: is this path strangled?
        boolean isStrangled = featureFlags.getBooleanValue("audit-strangled", false,
            EvaluationContext.of("userId", userId));

        // 2. Canary check: only a percentage of users go to the new service
        boolean inCanary = isStrangled && isInCanaryGroup(userId);

        if (inCanary) {
            try {
                return routeToNewService(req);
            } catch (Exception e) {
                // 3. Automatic fallback: new service failed → fall through to monolith
                errorCounts.computeIfAbsent(path, k -> new AtomicInteger()).incrementAndGet();
                // Production: if error rate > 1% in 60s, set flag to 0% via API
                System.err.println("[STRANGLER] New service failed for " + path
                    + ", falling back to monolith. Error: " + e.getMessage());
                return routeToMonolith(req);
            }
        }

        return routeToMonolith(req);
    }

    private boolean isInCanaryGroup(String userId) {
        // Deterministic hashing: same user always goes to same group
        // (prevents session bouncing between old and new service)
        int canaryPct = featureFlags.getIntegerValue("audit-canary-pct", 0);
        return Math.abs(userId.hashCode() % 100) < canaryPct;
    }

    private byte[] routeToNewService(HttpServletRequest req) {
        return newServiceClient.get()
            .uri(req.getRequestURI())
            .headers(h -> req.getHeaderNames().asIterator().forEachRemaining(
                name -> h.add(name, req.getHeader(name))))
            .retrieve()
            .onStatus(status -> status.is5xxServerError(),
                      resp -> Mono.error(new RuntimeException("New service 5xx")))
            .bodyToMono(byte[].class)
            .block();
    }

    private byte[] routeToMonolith(HttpServletRequest req) {
        return monolithClient.get()
            .uri(req.getRequestURI())
            .retrieve()
            .bodyToMono(byte[].class)
            .block();
    }
}
```

## 7. Production Lens

At Amazon (2002 Bezos mandate), the transition from a monolith to service-oriented architecture took **7 years** of Strangler Fig migrations, not a big bang rewrite. Each service was extracted one at a time, with traffic routing managed by the existing API gateway.

Martin Fowler cited a UK retail client (2004) where a Big Bang rewrite of a 10-year-old ordering system was attempted, abandoned after 18 months, and $4M spent, with zero production traffic migrated. The subsequent Strangler Fig approach delivered the first migrated service (the "Catalogue" context) in **6 weeks** and full migration in **14 months** — compared to the abandoned 18-month rewrite.

Concrete ROI for the GOL Audit example: the legacy audit database lock causes 10-second pauses, 3 times per hour. At 500k trades/day during trading hours (8 hours), each 10-second pause blocks ~1,157 trades × 3 pauses/hour × 8 hours = ~27,800 blocked trade events/day. At $12 average trade value with 2% abandonment: **$6,700/day**, **$2.4M/year**. Strangling the audit feature costs 1 sprint. ROI payback: **< 1 week**.

## 9. Summary / Flashcard

- **Big Bang Rewrites fail at 70%+**: the new system is built in isolation, becomes obsolete before launch, and the legacy continues accumulating bugs; the Strangler Fig extracts value incrementally every sprint.
- **Three phases — Intercept, Propagate, Eliminate**: route specific paths to the new service at the gateway layer, then expand coverage one Bounded Context at a time, then decommission the legacy shell.
- **Deterministic canary hashing** (`userId.hashCode() % 100 < canaryPct`) pins each user to one service version for the duration of their session, preventing confusing behaviour from session-level inconsistency.
- **`AbstractHandlerMapping.setOrder(int)`** with a low order value makes the Strangler Router take precedence over Spring MVC's default `RequestMappingHandlerMapping` — the cleanest in-process implementation for monolith-to-microservice within a single Spring Boot app.
- **Automatic fallback on 5xx** is non-negotiable: the new service is unproven; the first canary traffic must fall back transparently to the legacy if the new service errors, with automatic flag-disable when error rate > 1%.
