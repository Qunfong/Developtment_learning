# 13.3: Secret Management and the Entropy Tax


## The Critical Dialogue


**Student:** I'm storing our DB password in `application.yaml`. It's a private repo, so it's safe.


**Principal:** You've built a **Time Bomb**. A private repo is only as safe as the least-secure developer's laptop. To reach Principal level, we must move from "Hardcoded Secrets" to **Ephemeral Cryptographic Leases**. We will analyze the **Entropy Tax** and the physics of **Dynamic Secrets**.


---


## 1. The Physics of Secret Proliferation


### 1.1 The "Git Leak" Failure
Secrets in code are **Static**. Once leaked, they remain valid forever.


### 1.2 The Entropy Tax
Generating random numbers is expensive.
. **The Physics:** The Linux Kernel collects entropy from hardware interrupts.
. **The Tax:** If 10,000 pods ask for a new key at once, the entropy pool becomes **Saturated**, causing your Java app to block on `/dev/random`.

## 2. Source Archaeology: Vault and KMS


> [!abstract] The Mechanics: Dynamic Secrets
. **Step 1:** The pod asks **HashiCorp Vault** for a password.
. **Step 2:** Vault creates a new database user valid for only 1 hour.
. **The Audit:** If a pod is compromised, the attacker has a 60-minute window before access vanishes.
