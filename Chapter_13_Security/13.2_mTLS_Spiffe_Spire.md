## The Critical Dialogue

**Student:** We use HTTPS for our public API. But for internal calls, we just use plain HTTP because it's "Inside the network."

**Principal:** You are relying on the **Wall of Hubris**. In a modern fleet, the "Internal Network" is the most dangerous place because one compromised pod can sniff all traffic. To reach Principal level, we must master **Mutual TLS (mTLS)** and the **SPIFFE/SPIRE** framework. We move from "Network Trust" to **Cryptographic Proof of Identity**.

## 1. The Physics of mTLS

In standard TLS, the client verifies the server. In **mTLS**, the server *also* verifies the client.
- **The Perimeter:** Security moves from the firewall (L3/4) to the **Identity Layer (L7)**.
- **The Tax:** The initial handshake is expensive (~3ms for TLS 1.3 + certificate validation), but subsequent packets use **AES-NI** hardware acceleration (~0.001ms/packet).

## 2. Source Archaeology: SPIFFE and SPIRE

> [!abstract] The Mechanics: SVID
> - **SVID:** A short-lived X.509 certificate, valid for 1 hour by default.
> - **SPIRE Agent:** Lives on every node. It verifies the pod's identity (using K8s UID) and issues an SVID automatically.
> - **Rotation:** SVIDs are rotated every hour. If a pod is compromised, the cert is useless within minutes.

**`io.spiffe.workloadapi.WorkloadApiClient`** (`spiffe-lib-java`, `io.spiffe:java-spiffe-core`):
- `newClient(WorkloadApiClient.ClientOptions.defaultOptions())` → connects to the SPIRE Agent Unix Domain Socket at `unix:///tmp/spire-agent/public/api.sock`
- `fetchX509Context()` → returns `X509Context` containing the pod's SVID chain and trust bundles
- `watchX509Context(Watcher<X509Context>)` → **push-based rotation**: the SPIRE Agent streams new SVIDs before expiry, no polling required

**`io.spiffe.svid.x509svid.X509Svid`**:
- `getSpiffeId()` → returns the SPIFFE URI, e.g. `spiffe://ledger.prod/order-service`
- `getChain()` → the `List<X509Certificate>` to present during mTLS handshake
- `getPrivateKey()` → the `PrivateKey` for the handshake (never persisted to disk — lives in process memory only)

**`io.spiffe.bundle.x509bundle.X509BundleSet`**:
- Used as `TrustManager` — contains the SPIFFE Trust Domain CAs; only SVIDs signed by these CAs are accepted
- Peer's SPIFFE ID is validated against a policy (e.g. only `spiffe://ledger.prod/*` is allowed to call the order service)

**Certificate chain validation in Java:**
- `sun.security.ssl.X509TrustManagerImpl.checkClientTrusted()` is called during the server-side TLS handshake; SPIRE's `X509BundleSet` effectively replaces the default trust store
- Java's `SSLContext.init(KeyManager[], TrustManager[], SecureRandom)` is the integration point

## 4. Code Lab: Full SPIRE-backed mTLS gRPC Client

### BAD: Internal service call with no mutual authentication

```java
// BAD: Plain HTTP between internal services.

            Order.class
        );
    }

```

### GOOD: SPIRE SVID-backed mTLS with automatic rotation watcher

```java
import io.grpc.*;
import io.grpc.netty.shaded.io.netty.handler.ssl.SslContext;
import io.grpc.netty.shaded.io.grpc.netty.GrpcSslContexts;
import io.spiffe.workloadapi.*;
import io.spiffe.svid.x509svid.X509Svid;
import io.spiffe.bundle.x509bundle.X509BundleSet;
import java.util.concurrent.atomic.AtomicReference;
import javax.net.ssl.SSLException;

/**
 * mTLS gRPC client backed by SPIRE X.509 SVIDs.
 *
 * Key properties:
 * - SVID loaded from SPIRE Agent Unix socket — never from disk or env vars
 * - Rotation watcher: new SVID is applied before expiry (no restart needed)
 * - Peer identity validated: only spiffe://ledger.prod/* accepted
 */
public class SecureOrderServiceClient implements AutoCloseable {

    private final WorkloadApiClient spireClient;
    private final AtomicReference<ManagedChannel> channelRef = new AtomicReference<>();

    public SecureOrderServiceClient() throws Exception {
        // 1. Connect to SPIRE Agent via Unix Domain Socket
        this.spireClient = WorkloadApiClient.newClient(
            WorkloadApiClient.ClientOptions.defaultOptions()
        );

        // 2. Fetch initial SVID and build channel
        X509Context ctx = spireClient.fetchX509Context();
        channelRef.set(buildChannel(ctx));

        // 3. Watch for SVID rotation — SPIRE pushes new cert before expiry
        spireClient.watchX509Context(new Watcher<>() {
            @Override
            public void onUpdate(X509Context newCtx) {
                // Swap channel atomically — in-flight RPCs complete on old channel
                ManagedChannel old = channelRef.getAndSet(buildChannel(newCtx));
                old.shutdown();  // graceful — waits for in-flight calls
                System.out.println("SVID rotated, new SPIFFE ID: "
                    + newCtx.getDefaultSvid().getSpiffeId());
            }

            @Override
            public void onError(Throwable e) {
                System.err.println("SPIRE watch error: " + e.getMessage());
                // Production: implement exponential backoff reconnect here
            }
        });
    }

    private ManagedChannel buildChannel(X509Context ctx) {
        X509Svid svid = ctx.getDefaultSvid();
        X509BundleSet bundles = ctx.getX509BundleSet();

        try {
            SslContext sslCtx = GrpcSslContexts.forClient()
                // Present our SVID as client certificate
                .keyManager(svid.getPrivateKey(),
                            svid.getChain().toArray(new java.security.cert.X509Certificate[0]))
                // Trust SPIFFE bundle CAs only — no system trust store
                .trustManager(bundles.getBundles().values().stream()
                    .flatMap(b -> b.getX509Authorities().stream())
                    .toArray(java.security.cert.X509Certificate[]::new))
                .build();

            return ManagedChannelBuilder
                .forAddress("order-service.internal", 443)
                .useTransportSecurity()
                .overrideAuthority("spiffe://ledger.prod/order-service")
                .build();
        } catch (SSLException e) {
            throw new RuntimeException("Failed to build mTLS channel", e);
        }
    }

    public ManagedChannel channel() { return channelRef.get(); }

    @Override
    public void close() {
        spireClient.close();
        channelRef.get().shutdown();
    }
}
```

## 5. Production Lens

| Phase | Latency | Notes |
|:---|---:|:---|
| TLS 1.3 full handshake | ~3 ms | One-time per new connection |
| TLS 1.3 session resumption | ~0.5 ms | `session_ticket` reuse |
| AES-NI data encryption (1KB) | ~0.001 ms | Hardware-accelerated, amortized to zero |
| SVID fetch from SPIRE Agent | ~2 ms | Unix socket, negligible on hot path |
| SVID rotation (push-based) | 0 ms hot-path | Background watcher handles it |

At Uber's scale (2021 blog post), enforcing mTLS across ~4,000 internal services via Envoy sidecars added **~2ms per new connection** but reduced their blast radius per compromised pod from "entire internal network" to "single SVID's TTL window (1 hour)." The security improvement was worth more than the 2ms cost on connection establishment.

SVID rotation every 1 hour: if a pod's SVID is stolen, the attacker has at most **60 minutes** before the credential is worthless — versus static TLS certificates that can be valid for 1–2 years.

## 7. Summary / Flashcard

- **mTLS shifts the trust perimeter** from the network (L3/L4 firewall) to cryptographic identity (L7 SVID); a compromised pod inside the network cannot impersonate another service because it lacks a valid SPIRE-issued SVID.
- **`WorkloadApiClient.watchX509Context(Watcher)`** is the push-based rotation API; the SPIRE Agent streams a new SVID before the current one expires, enabling zero-restart, zero-downtime certificate rotation.
- **SVID TTL of 1 hour** limits the blast radius of a credential theft to 60 minutes; contrast with traditional TLS certs (1-2 year validity) where a stolen cert enables impersonation for years.
- **TLS 1.3 handshake costs ~3ms** one-time per connection; amortized over HTTP/2 multiplexed requests (e.g. 100 RPCs per connection) the per-request overhead is ~0.03ms — negligible vs the security guarantee.
- **eBPF cannot inspect mTLS payload** because encryption occurs in the kernel's TLS implementation (or in Netty's JDK SSL engine) before eBPF's socket-level hooks; the correct approach for observability is distributed tracing with propagated headers at the application layer.
